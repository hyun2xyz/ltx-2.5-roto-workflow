# 다음 영상: Python 직접 출력과 소요 시간

투명 결과 파일만 필요하면 AE를 열지 않아도 됩니다. 복원된 전경 RGB와 정밀 알파를 Python에서 결합해 straight RGBA EXR 시퀀스로 저장합니다. AE는 레이어 편집·추가 합성이 필요한 경우에만 연결합니다.

## 루마와 알파의 차이

흑백 루마 매트를 A로 사용하는 원리는 같습니다. 다만 이 파이프라인의 최종 매트 EXR은 **RGB가 흰색이고 A에 실제 커버리지가 들어 있습니다.** 여기서 RGB 루마를 다시 읽으면 전체가 불투명해집니다. `export-rgba`는 매트의 A 채널을 사용합니다.

저장값은 `(F.R, F.G, F.B, A)`이며 F에 A를 미리 곱하지 않는 **straight alpha**입니다. 합성할 때 `F*A + background*(1-A)`를 한 번 적용합니다. 원본 RGB에 A만 붙이면 원래 배경색이 섞인 머리카락에 파란 테두리가 남을 수 있어, 이미 계산한 ML 복원 전경 F를 사용합니다. 알파를 다시 깎거나 흐리게 만들지 않습니다.

## 실행

모델과 empty conditioning은 기존의 고정 버전 캐시를 재사용합니다. 새 영상의 prepare/submit/collect/release 단계는 [파이프라인 문서](pipeline.md)를 따릅니다. 현재 프로필은 4096×2160, 25fps, 65프레임(2.6초)입니다. 길이·fps·해상도가 다른 영상을 자동으로 같은 시간이나 독립 청크 연결로 처리한다고 가정하지 않습니다.

```text
python -m pipeline refine --run runs/shot --out runs/refined4k --execution batch
python -m pipeline export-rgba --producer runs/refined4k --out runs/rgba_f32 --format exr
```

미디어 환경의 NumPy/OpenImageIO를 사용합니다. 확인용 PNG가 필요하면 새 출력 폴더에 `--format png8`로 실행합니다. PNG는 8비트 반올림·범위 제한이 있는 리뷰 파일이며 EXR F32 마스터와 구분합니다. EXR의 RGB는 BT.709 code values입니다. 소비 앱에서 straight alpha 및 숫자를 보존하는 색 해석을 명시해야 합니다. 일반적인 scene-linear EXR로 자동 해석하면 밝기가 달라질 수 있습니다.

출력에는 프레임 순서·원본 번호·fps·입출력 SHA가 담긴 `export-receipt.json`이 생깁니다. 기존 폴더는 덮어쓰지 않습니다. EXR은 모든 프레임을 다시 읽어 F32 비트를 확인합니다. 원본 F/A/prior는 유지하며 추론·AE·녹화는 시작하지 않습니다. 투명 동영상 인코딩은 이 CLI의 범위가 아닙니다.

## 줄인 작업

- 65프레임 × GPU/CPU/pack의 195개 프로세스를 배치 모드에서 3개로 줄입니다. GPU 모델·processor·타일 배치는 한 번 로드하며 프레임과 타일 계산은 순차입니다. BF16/F32 정밀도와 수학적 처리는 유지합니다.
- 입력·설정·구현과 파일/픽셀 SHA가 일치하는 완료 단계만 재사용합니다. 불완전하거나 바뀐 중간 파일은 중단 후 보존합니다. 기존 isolated 모드도 남겨 두었습니다.
- 투명 파일 납품에는 AE 실행·프로젝트 구성·native 렌더를 생략합니다. AE가 필요하고 환경이 동일하면 입력 260개 검사와 전체 영상 검수를 유지하며 native 출력은 [review5](after-effects.md)의 5개 표본으로 확인할 수 있습니다. 환경·모델·색 설정 변경 시 기존 full100 검증을 사용합니다.
- OBS 녹화, 인터페이스 연출, 브레이크다운 렌더는 요청할 때만 합니다. 모델 다운로드·환경 구축·조건 임베딩 생성도 매 영상 반복하지 않습니다.

## 시간 근거와 한계

RTX 4070 Ti SUPER 16GB, RAM 32GB, 직접 연결한 SSD에서 기존 65프레임 기록은 다음과 같습니다.

| 단계 | 기존 실측 |
|---|---:|
| LTX BF16 FHD prior | 1,012.713초 / 16분 53초 |
| 4K 보정 전체 배치 | 1,466.432초 / 24분 26초, 5개 재사용·60개 신규 |
| 신규 60개 프레임의 처리 합 | 1,317.899초 / 평균 21.965초 |
| 그중 ViT CUDA forward | 256.199초 |
| 프로세스 시작 등 외부 overhead 합 | 536.261초; 전부 모델 로딩 시간이라는 뜻은 아님 |

기존 방식에서 65개 모두 신규인 경우 핵심 계산 약 42분, AE 연결·검수 포함 **45–60분**이 계획 기준입니다. 최초 설치부터 걸린 10시간대 시간은 다음 영상의 처리 시간이 아닙니다.

배치 최적화는 원본 프레임 83/107, 두 프레임만 실제 재처리했습니다. GPU 단계 36.407초(한 번의 초기화 21.813초 포함), CPU 전경 13.574초, 포장 3.038초였습니다. 두 프레임의 알파와 전경 F32는 기존 완성본과 **모든 비트 일치, 최대 오차 0**입니다. 콜드 초기화가 포함된 작은 표본이므로 이를 단순히 프레임 수에 곱하거나 전체 65프레임 속도 개선 실측으로 표현하지 않습니다. 전체 신규 작업은 **35–45분을 잠정 계획 범위**로 두되, 다음 실제 샷 로그로 갱신해야 합니다. CLI 기본값은 기존 isolated이며 batch는 명시 선택합니다.

AE를 건너뛰는 것만으로 17분짜리 LTX 추론이나 4K 보정 시간이 사라지지는 않습니다. **완성된 기존 65프레임의 결합·저장·F32 재검증은 69.453초**였습니다. 4096×2160 straight RGBA EXR 65개, 합계 7,330,618,091바이트입니다. 이것은 새 영상의 알파 추론 시간을 포함하지 않습니다. 전체 65개에 EXR write/readback 비트 검사를 적용했고, 원본 번호 75–139와 25fps를 보존했습니다. [작은 검증 요약](optimization-validation.json)에 측정 범위를 기록했습니다.

## 검증과 백그라운드 실행

30개 집중 회귀 테스트(API 중복 제출·F32·배치 재개/변조·RGBA 출력·AE review5)가 통과했습니다. 배치 실제 GPU 검증은 위 두 프레임뿐입니다. AE review5는 모의/수치 회귀로 검증했고 새 AE native 렌더를 실행하지 않았습니다. 전체 65프레임의 움직임과 1:1 머리카락 시각 검수는 계속 필요합니다.

로컬 작업 스케줄러의 독립 워커로 긴 명령을 실행하고 로그·종료 코드·출력 검증을 남깁니다. 저장소 CLI 자체는 스케줄러가 아니며 일반 foreground 프로세스의 앱 종료 후 지속을 보장하지 않습니다. 모델 계산을 기다리는 동안 LLM을 계속 호출할 필요는 없습니다. 작업 완료 이벤트만으로 AI가 자동으로 깨어난다고 주장하지 않습니다.
