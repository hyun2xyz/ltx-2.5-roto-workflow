# Fruit 레퍼런스 기반 브레이크다운

완성 로토를 확인하는 세로형 편집 규격입니다. 기존 Fruit 브레이크다운의 화면과 캡션 배치를 기준으로 했습니다. 원본 영상과 캡처는 저장소에 포함하지 않습니다.

## 화면

- 출력: 1080×1350, 30fps, 756프레임, 25.2초.
- 배경 RGB: `[252,254,253]`.
- 본문 영상 영역: `[x=0,y=371,w=1080,h=608]`.
- 도입부 결과/원본: `[0,55,1080,608]`, `[0,688,1080,608]`.
- 4096×2160 원본 전체를 1080×570으로 contain합니다. 상하 19px을 채워 영역을 맞추며 좌우 머리카락을 자르지 않습니다.
- 알파 여백은 검정, 합성은 해당 배경색, 원본은 캔버스 색을 사용합니다.

## 캡션

Arial 21px, 24px 높이 흰색 상자, 기준선 18px, 좌우 padding 3px, 행 간격 27px입니다.

- `Process`: `[24,395]`.
- 단계: `[40,422+27*i]`. 지난 단계는 회색 `[125,128,126]`, 현재 단계는 검정입니다.
- 오른쪽 크레딧 기준 x=1056, y=904/931. 도입부는 y=1221/1248입니다.
- 단계 이름: Original 4K → LTX-2.5 22B BF16 / FHD prior → 4K ViTMatte / FLOAT32 → ML foreground RGB → AE 32-bpc alpha composite.

## 타임라인

| 구간 | 길이 | 재생 |
|---|---:|---|
| 결과와 원본 동기 비교 | 5.2초 | 0.5× |
| 원본 | 2.6초 | 1× |
| 실제 ComfyUI 노드 이동 캡처 | 6초 | 기록된 장면을 6×로 편집 |
| 원래 알파 → 보정 알파 → 체커 → 실제 AE 합성 | 5.2초 | 하나의 연속된 0.5× 원본 clock |
| 결과 시작 프레임 정지 | 1초 | `START HOLD` 표기 |
| 최종 결과 | 5.2초 | 0.5× |

와이프는 오른쪽에서 왼쪽으로 6개 표본, 경계 x=`1080,864,648,432,216,0`, 흰 선 2px입니다. 와이프 양쪽에는 같은 시각의 프레임을 사용합니다. 보간이나 optical flow로 알파 프레임을 만들지 않습니다.

## 실제 캡처와 색상

이번 캡처는 이미 저장된 실제 BF16/FHD 생성 기록에서 모델→guide→sampler→decode 화면 이동을 골랐습니다. 소스 PTS 294–306, 316–328, 414–426초를 각각 2초로 편집했고, 고정 crop `[0,40,1600,940]`으로 과거 결과 갤러리를 제외했습니다. 진행 표시나 노드 내용은 재작성하지 않았으며 새 OBS 녹화도 하지 않았습니다.

이 화면을 4K ViTMatte 추론이나 새 AE 작업의 녹화로 표시하지 않습니다. AE 단계는 검증된 실제 native-clean EXR에서 가져옵니다. 이 EXR의 RGB는 이미 `F*A`이므로 합성식은 `RGB + background*(1-A)`입니다.

출력은 실제 RGB↔BT.709 limited-range 행렬 변환을 적용합니다. 메타데이터 태그만 바꾸어 색상 변환을 대신하지 않습니다. 최종 MP4 전체 decode, 프레임 수, 소스 clock, caption bounds와 전환 주변을 함께 검수합니다.
