# 로토 경계 보정과 투명 출력

기본 로토는 `refine` 후 `export-rgba`로 완성합니다. 원본 영상과 나란히 재생해 경계가 튀는 프레임을 찾으면 같은 producer 폴더를 재사용해 보정본을 별도로 출력할 수 있습니다. 두 보정 모두 원본 격자에서 전경색 F와 투명도 A를 함께 처리합니다.

```sh
python -m pipeline export-rgba --producer runs/refined4k --out runs/rgba_fixed --repairs config/shot-repairs.local.json
```

기본 출력은 straight RGBA FLOAT32 EXR입니다. 빠르게 합성해 보려면 다른 출력 경로와 `--format png8`을 사용하세요. 결과에는 샷의 원래 프레임 번호와 시간, 적용한 레시피, 각 출력 파일의 SHA-256이 담긴 `export-receipt.json`이 함께 저장됩니다. 모델 재실행이나 AE 연결은 필요하지 않습니다.

| 증상 | 복사할 예제 | 샷에 맞출 값 |
|---|---|---|
| 어두운 머리카락 사이로 푸른 하늘이 불투명하게 남음 | [hair-sky.json](../config/repairs/hair-sky.json) | 머리카락 틈의 중심을 몇 프레임에서 지정합니다. 중심 사이의 위치를 보간하고 각 프레임에서 주변 하늘색과 모발색을 다시 측정합니다. |
| 밝은 벽 앞에서 불투명한 옷의 바깥쪽 경계가 순간적으로 번짐 | [jacket-edge.json](../config/repairs/jacket-edge.json) | 불량 프레임 구간과 앞뒤의 깨끗한 참조 프레임을 고르고 경계 탐색 창을 지정합니다. 원본 RGB에서 옷의 윤곽을 찾고 참조 알파에서 경계의 부드러움을 측정합니다. |

예제의 프레임과 좌표는 각각 검수한 촬영분에 맞춘 값입니다. 사용할 예제를 `config/shot-repairs.local.json`으로 복사하고 아래 항목을 새 샷에 맞게 설정하세요.

- `grid`는 원본의 `[너비, 높이]`입니다. `source_start_frame`은 producer의 `frame-ledger.json` 첫 행에 있는 `source_frame_index`와 일치해야 합니다. `first_source_frame_sha256`에는 같은 행의 `inputs.source.sha256`을 넣습니다.
- 규칙 안의 프레임 번호는 샷의 첫 프레임을 0으로 셉니다. `frames: [56, 57]`은 57번째와 58번째 프레임을 포함합니다. 범위 밖의 프레임도 원래 타이밍으로 출력합니다.
- 머리카락 규칙의 `anchors`는 `[로컬 프레임, x, y]` 목록입니다. 예제에서는 원본 전체를 1080×570으로 축소한 화면의 왼쪽 위가 원점입니다. 머리카락 틈이 움직일 때 그 중심 위치를 시간순으로 지정하세요.
- 옷 경계 규칙의 `reference_frames`는 불량 구간 전후 한 프레임씩입니다. `edge_columns`와 `first_row`는 `calibration_grid` 좌표이고, `*_shifts`는 추정한 경계에서 잰 **원본 해상도 가로 픽셀 거리**입니다. 이 규칙은 각 가로줄에서 왼쪽에 배경, 오른쪽에 옷이 있고 그 사이에 경계가 하나인 영역에 사용하세요.
- 출력이 끝나면 검은색·밝은색 배경에서 잔머리 사이로 새 배경이 비치는지, 옷 가장자리가 앞뒤 프레임과 이어지는지 확인하세요. 그린스크린이나 반투명 천처럼 색·재질이 다른 샷에서는 이 예제의 결정 기준을 그대로 적용하기 어렵습니다.

## 실제 샷 대조

머리카락 예제의 4K 65프레임을 보관된 최종 보정과 대조했습니다. 30프레임의 국소 보정과 나머지 35프레임을 포함해 straight RGBA의 모든 F32 비트가 일치했습니다. 옷 경계 예제는 로컬 55–58 구간을 새 EXR 시퀀스로 출력해 비교했습니다. 보정한 56·57과 앞뒤 55·58 모두 RGBA 최대 절대 오차가 0이었습니다.
